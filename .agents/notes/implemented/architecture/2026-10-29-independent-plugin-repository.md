# Agent Note: DSH 插件独立维护与网关固定副本

Status: implemented

## 问题

插件此前由 Bridge 导出时合入 host 和许可证，单独复制 plugin 目录会缺少运行时。用户要求独立仓库维护，同时保留官方客户端一键安装与现有网关行为。

## 决策

本地独立仓库包含完整运行时、两份原许可、来源提交与逐文件哈希。后续插件实现以本仓库为维护源；Bridge 暂保留固定副本，通过提交锁与内容校验识别漂移，不在启动时下载代码。仓库导入保留作者与许可证说明，不伪造作者提交历史。

打包脚本仅收集七个明确文件，以固定顺序、权限和时间戳生成可复现 ZIP/TGZ。临时凭据、测试目录、来源元数据和市场草稿均不进入安装包。用户已明确授权公开独立源码仓库；目标为 `try2love/dsh-codex-mobile-bridge`。没有自动发布工作流，npm 和市场发布仍需另外授权。

## 备选方案

立即删除 Bridge 内置文件能实现单一物理副本，但会影响冻结程序分发和官方一键安装，当前保留显式锁定副本。仅复制源码而不记录同步边界最简单，但容易两边独立修改而漂移，因此加入提交与内容检查。

## 验证

Node 测试覆盖真实插件装载、回环认证、实例身份稳定、重复写入者拒绝和包内文件白名单；打包测试比较两次产物哈希并核对解包内容。独立源码仓库已按授权创建；市场与 npm 尚未发布。本轮不宣称独立包已完成三系统重新安装。

## 影响

插件可独立测试、打包和审查。代价是 Bridge 仍需显式同步内置副本；协议兼容性与实际运行版本核验不因此放宽。

## 历史记录核对

Bridge 的通用插件绑定、双路线兼容记录与本决定部分重叠，继续持有绑定、版本和生命周期规则；本记录只描述源码维护边界。消息模型、通知、归档和共享菜单记录涉及运行时行为，未被本轮取代。新仓库此前没有其他决策记录。
