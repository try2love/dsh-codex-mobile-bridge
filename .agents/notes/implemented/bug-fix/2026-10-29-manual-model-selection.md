# Agent Note: 手动模型选择保留原生校验

Status: implemented

## 问题

空模型目录使手动输入在到达原生核心前就被拒绝；目录异常也会阻塞手动兜底。仅提供输入框不能解决这个问题。

## 决策

模型设置允许显式 `manualModel` 跳过可选目录读取，`manualEffort` 表示用户明确输入思考强度。仍校验输入结构，再调用原生 `selectModel`，由原生核心验证模型和强度。返回选择必须与请求匹配；原生拒绝、返回不匹配都不能显示成功，不自动重试。

## 备选方案

目录白名单能及早拒绝无效输入，但目录为空或不可用时也阻止合法手动选择，因此仅保留普通选择路径的目录检查。绕过核心直接改状态可显示选中却不保证实际生效，因此不采用。

## 验证

旧实现的合成 HTTP 测试复现 400“请选择可用模型”。更新后同一测试验证手动模型与强度转交、目录抛错时仍可显式手动设置、原生拒绝和原生返回其他模型时均不返回 accepted；三项 Node 测试全部通过。测试使用临时档案和回环地址，没有调用付费模型或真实会话。

## 影响

有手动兜底不表示核心支持任意模型；核心不支持的输入仍明确失败。公开协议动作不变，新增可选手动标志和能力字段。
